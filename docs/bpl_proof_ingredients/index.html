    Component guide

    A component guide to branching-program acceptance

    Logical algorithms and their low-space implementations. A navigation layer for the manuscript; section and page numbers refer to it.

    The input is a binary read-once branching program given by its list of vertices and transitions. We want a deterministic estimate of its acceptance probability. The construction reduces this task to evaluating sparse sampled tables recursively. One proposed evaluator compares vertex names exactly and uses \(O(\log n\log\log n)\) work bits for large input length \(n\). The logarithmic-space proposal uses fingerprints for comparisons at tight space budgets. Both space bounds remain conditional on the proof obligations below.

    An L- routine defines an explicit finite computation. A P- routine returns a digit, a port, a bounded action result, or another piece of the low-space computation. The T- routines are physical programs that expose the end of a path and own the information needed to return or discard it. For a fixed task, seed, and comparison policy, prove that the physical queries give the logical computation's values and finite decisions. This lets the same logical accuracy argument serve both evaluators. The interfaces state the required behavior and local state bounds. The proof notes identify the checks needed to use them.

    Proof status

    Both end-to-end space bounds are conditional on the open proof obligations.

    • Exact names: compares vertex names exactly, using \(O(\log n\log\log n)\) work bits. Conditional.
    • Full space: the logarithmic-space proposal, using fingerprints at tight space budgets. Conditional.

    Use the switch at the top to choose a comparison mode. Throughout the guide, an explicit interface is a component’s stated behavior, and What to prove marks an open proof obligation.

    Worked example: one correction product

    The toy problem from §1, step by step

    The toy problem

    The correction step needs the product \(EC\) of a correction matrix \(E\) and the transition matrix \(C\). One term of its \((x,y)\) entry follows a correction edge from the source \(x\) to a sampled midpoint \(z\), then a transition from \(z\) to the destination \(y\). In the example at stage \(l\), the two sampled entries are \(1/2\) and \(1/4\), so with the midpoint retained the term contributes \(f_l/(8\pi_{f_l})\) to the logical sample.

    The problem: produce the digits of this one contribution on demand, in low space. Starting at \(x\), the evaluator must move to \(z\) along the correction edge, read the transition entry there, and return to \(x\). It keeps only a bounded port token for the way back rather than the source's name, and it never stores either entry in full. The steps below show which routines do each part.

    2. P-CHILD Construct a child task with explicit field resets Describe the two child queries. The right query uses the midpoint as its source. §7.1.
    3. P-CAP (forward) Delete an entire overfull incoming column At the source, follow the correction's outgoing port to the midpoint. On success it returns the incoming port that identifies the edge in reverse. §6.2.
    4. P-ROW Final numerical row query At the midpoint, read the requested digit of the transition entry and restore the cursor. §6.2.
    5. P-CAP (inverse) Delete an entire overfull incoming column Return from the midpoint to the source. §6.2.
    6. P-ARRIVAL One validated increment value Supply the signed weighted digit for this record: the signed arrival. §7.2.

    Then: §8.1 Group arrivals under the chosen policy → §8.2 Choose a default and retain exceptions → §6.2 Assemble final values and ports.

    Read §1.1 in full

    Start with the continuation equation \(p=w+Cp\). Here \(p\) is the continuation probability vector, \(w\) is the accumulated reward, and \(C\) is the remaining transition matrix. A correction matrix \(E\) changes the reward to \(w+Ew\) and the transition matrix to \(C-E+EC\). The continuation equation is preserved because

    \[(w+Ew)+(C-E+EC)p=w+Cp+E(w+Cp-p)=p.\]

    The same product \(EC\) occurs while constructing the correction. A term in its \((x,y)\) entry follows a correction edge from source \(x\) to midpoint \(z\), then a transition from \(z\) to destination \(y\).

    Sampling the midpoint saves work when the left factor has few enough outgoing entries at the sampling scale. The right factor's weights must also be small enough that increasing the weight of a sampled term keeps the contribution controlled. This is the reason to reduce transition weights before asking for a sparse recursive estimator. The vertex sampling example in Vadhan's outline motivates these two requirements.

    Take one valid product contribution at stage \(l\). For this example the parent and transition bin both use the stage scale \(f_l\), so the magnitude-bin weight in D-WEIGHTS is one. Suppose the sampled correction and transition entries on this path are \(1/2\) and \(1/4\), respectively. With the midpoint retained, their contribution to the logical sample is \(f_l/(8\pi_{f_l})\), where \(\pi_{f_l}\) is the midpoint hit probability. Averaging later includes the walk weight and the sign of the child-budget difference. L-FAMILY and D-ROWFAMILIES specify these operations separately.

    1. P-CHILD describes the two queries. The right query uses the midpoint as its source and its task depends on the shared seed and the right factor's parameters. All sources that use this right factor at the same midpoint see the same table.
    2. For a right-factor digit, P-INTRINSICVALUE calls P-CAP at the source with the correction's outgoing port. On success the cursor moves to \(z\) and the call returns the incoming port that identifies the edge in reverse. The incoming cap makes that port a bounded token.
    3. P-ROW reads the requested digit of the transition entry at \(z\) and restores the cursor to \(z\). P-CAP in inverse mode then returns to \(x\). P-NUMSTEP combines the operand digits using the product expression and its declared scale. A failed left move contributes zero and leaves the cursor at \(x\).
    4. P-ARRIVAL supplies the signed weighted digit for this record. P-MERGE includes it with the other arrivals assigned to its representative. Later queries use the resulting compressed row and the fixed final ports.

    The logical product analysis uses the row cap on the transition table to bound how many destinations reuse one left-factor error. It uses the incoming cap on the correction table to bound how many sources reuse one right-factor error at \(z\). The physical argument uses the same capped relation to enumerate outgoing ports and restore the cursor. These two arguments meet at the specification of one sampled table. The exact transition matrix can have dense rows and columns.

    §1.2 Reading order and recursive order

    The ingredient order explains the construction. Within a recursive call, the order is different. A parent forms sample terms from completed lower-budget tables, averages differences between child estimates, then groups and compresses each increment. The final gates turn the completed raw row into the next table. The degree bounds are therefore both hypotheses on child tables and conclusions for the parent.

    The correspondence proof uses a common induction on the call allowance. Each local proof identifies its logical output, including ordered representatives, padded ranks, and finite tests where relevant. Its physical part accounts for live fields, restoring failure, and cleanup. The whole proof can reuse the logical error estimates after these correspondences are established. Section §13 states how the pieces fit.
