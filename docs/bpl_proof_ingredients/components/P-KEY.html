    Physical routine · Full space only

    P-KEY
    Short block key at a presented endpoint

    Manuscript: Algorithm P-KEY, §9.4 Compare names or fingerprints, p. 37.

    Full-space mode only. This component is part of the logarithmic-space evaluator's fingerprint comparison and is not used with exact name comparison.

    Input and output

    Explicit interface · Short block key at a presented endpoint

    \(\Call{P-KEY}(\rho,v,b)\longrightarrow(k)\)

    Return the block-\(b\) fingerprint bucket in \(\{1,\ldots,B\}\) for the supplied endpoint \(v\). The effective fair bits are those in \(\rho\); a physical caller presents \(v\) through the single cursor. No graph query is made. Unpermitted future block requests return INVALID.

    State and cost. \(O(\log B)\) arithmetic scratch plus sequential access to endpoint bits; no endpoint copy survives a child because there are no child calls.

    Algorithm

    Requires. Effective block access is allowed by D-HASHBLOCKS; prime existence is X-PRIME.

    1. Take the least prime \(q_{\rm hash}\in[B^3,2B^3]\), found by bounded integer trial division. Let \(\ell=\lceil\log_2q_{\rm hash}\rceil\).
    2. Read the three \(\ell\)-bit chunks for block \(b\), reduce them modulo \(q_{\rm hash}\), and call them \(R,A,C\).
    3. Scan the \(c_{\rm ID}B\) padded name bits by Horner's rule to compute \(P_v(R)\pmod q_{\rm hash}\).
    4. Put \(z=AP_v(R)+C\pmod q_{\rm hash}\) and return \(k=1+\lfloor Bz/q_{\rm hash}\rfloor\).

    What to prove

    Open proof obligation · §9.4

    Establish the predicate returned in each mode, restoration for arbitrary initial shared bits, and the retained fields at each visit. Analyze collision-induced changes on the logical side using Section §8.3.
