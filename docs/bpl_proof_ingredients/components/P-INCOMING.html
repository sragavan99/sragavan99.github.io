    P-INCOMING
    Incoming score rank without a saved endpoint

    Manuscript: Algorithm P-INCOMING, §6.2 Assemble final values and ports, p. 17.

    Input and output

    Explicit interface · Incoming score rank without a saved endpoint

    \(\Call{P-INCOMING}(\mathcal T,\mathrm{kind},t)\longrightarrow(b)\)

    Kinds are DETECTOR-RANK, I-RANK and GATE. Rank kinds return the corresponding incoming rank digit. GATE returns a digit of \(1-\chi_{1/4,1/2}(r)\) for the incoming-\(I\) rank \(r\). The rank scan and local gate arithmetic now have separate interfaces.

    State and cost. Rank mode adds only finite control; gate mode adds a fixed numerical continuation. All destination tours restore before another rank digit is requested.

    Modes

    ModeUsed byServes ingredient
    RANKBoth evaluatorsReversible walks
    GATEBoth evaluatorsControlling worst-case degree

    Algorithm

    Requires. Correct uncapped score graph and all-seed rank/cutoff ranges.

    1. For a rank kind, \((b)\gets\) P-INCOMINGRANK\((\mathcal T,\mathrm{kind},t)\); return \(b\).
    2. For GATE start the fixed complementary-cutoff expression with \(s=\varnothing,a=\bot\) and repeat \((s',o)\gets\) P-NUMSTEP\((E_{\rm gate},t,\mathrm{digit},s,a)\); set \(s=s'\).
    3. For its rank REQUEST\((j)\), \((a)\gets\) P-INCOMINGRANK\((\mathcal T,\mathrm{I\!\!\!-RANK},j)\).
    4. On DONE\((b)\) erase state and return \(b\).

    What to prove

    Open proof obligation · §6.2

    Show that the fixed classes cover the gated support, that the cap deletes only zero gated values, and that each query agrees with the corresponding finite test or value. Check that successful pairs are inverse and that failure and cleanup restore all required state.
