    P-AFFINE
    Finite-prefix affine arithmetic requests

    Manuscript: Algorithm P-AFFINE, §11.2 Stream digits through bounded requests, p. 42.

    Input and output

    Explicit interface · Finite-prefix affine arithmetic requests

    \(\Call{P-AFFINE}(F,t,\kappa,s,a)\longrightarrow(s^+,o)\)

    This coroutine implements a declared finite affine sum or continuous piecewise-affine formula \(F\) on normalized digit operands. A comparison request has a finite prefix length in \(F\) and returns its sign; a certificate request returns \(N_t(F)\bmod2^\kappa\). \(\kappa\) is a fixed program tag. It emits operand requests but calls no operand.

    State and cost. Comparison: fixed coefficient/branch tags, bounded accumulator, one pending digit and \(T-j+1\) markers. Residue: \(H+\kappa=O(d)\) bits and \(O(d)\) list indices. These phases do not coexist.

    Algorithm

    Requires. D-RECIPES normalized ranges; finite coefficient bounds and tie rules; complete resume state. Affine coefficients have the declared common dyadic denominator removed, so the residue-loop \(c_i\) are integers.

    1. On START check the expression kind, finite list bounds, ranges and guard. For an affine sum set \(A=\sum_i|c_i|\), \(h=\lceil\log_2(96A)\rceil+1\), \(T=\max(0,t-e+h)\) and \(H=T+e-t\); zero coefficients return zero.
    2. For each finite-prefix branch comparison set \(z=0\). For \(j=0,\ldots,T\), set \(u=0\); for each operand \(i\), emit \(b_i\gets\mathrm{REQUEST}(i,j)\) and add \(c_i b_i\) to \(u\). Update \(z\gets2z+u\), storing it up to the declared coefficient-bound threshold and then its absorbing sign. Finish all places and choose the stated tie branch.
    3. Erase comparison markers. For the selected affine form set residue \(R=0\) modulo \(2^{H+\kappa}\).
    4. For each operand and \(j=\max(0,T-H-\kappa+1),\ldots,T\), \(b\gets\mathrm{REQUEST}(i,j)\); set \(R\gets R+c_i b2^{T-j}\pmod{2^{H+\kappa}}\).
    5. Return DONE\((\lfloor R/2^H\rfloor\bmod2^\kappa)\). A finite comparison returns DONE\((\operatorname{sign}z)\) after its comparison phase.

    What to prove

    Open proof obligation · §11.2

    Prove agreement with the finite equations for every primitive and client, including ties and scale shifts. Instantiate the resume transitions, then count the fields across each operand call. For a reciprocal, keep the originating place available while erasing the long early word before a late operand request.
