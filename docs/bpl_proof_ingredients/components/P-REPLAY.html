    Physical routine · Both modes

    P-REPLAY
    Regenerate parameters in shared scratch

    Manuscript: Algorithm P-REPLAY, §9.1 Reconstruct a task from relative fields, p. 30.

    Input and output

    Explicit interface · Regenerate parameters in shared scratch

    \(\Call{P-REPLAY}(\mathcal T,\mathrm{field},q)\longrightarrow(r)\)

    \(\mathcal T\) is a completed relative handle into the marked root-to-owner record chain, or its frozen bounded-edit view. Return the requested pure field, validity flag, child schema, coefficient bit, or expression tag. Full tuples exist only in the shared reconstruction buffer. Replay has no estimator, presence or terminal callback.

    State and cost. One \(O(B)\) shared buffer; only a relative field request is retained by the caller. No scratch crosses an opaque query.

    Algorithm

    Requires. Complete frozen portal; bounded link path and a declared pure field request.

    1. Start from the immutable root fields and master seed in one scratch buffer.
    2. Scan the completed marked links from root to \(\mathcal T\); reject malformed/partial links before interpreting their fields.
    3. At each sample link, \((\sigma',b,\omega)\gets\) P-WORD\((\sigma,H,w,\mathrm{RAW})\); replace the effective seed by \(\sigma'\).
    4. Then \((Q)\gets\) P-CHILD\((\mathcal T_{\rm parent},\tau,r,\mathrm{side})\); replace the requested tuple fields by that child result. Non-sample prefix links change only their stated slack/mode.
    5. For a requested public base scalar, \((v)\gets\) P-BASE\((x,\mathrm{mode},p)\); use its pure result. Otherwise select the requested bit/field of the reconstructed tuple or literal expression.
    6. Return \(r\) and erase the reconstruction buffer; read every link through the supplied virtual view.

    What to prove

    Open proof obligation · §9.1

    Specify the concrete marked fields and prove replay on both genuine and admitted probe views, with shared scratch erased before a recursive query.
