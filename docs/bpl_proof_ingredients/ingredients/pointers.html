    Pointer scheme for sparse rows

    The big picture

    Map ingredient 7 · toy API

    Navigate using one current vertex and short relative paths.

    Input
    Nested sparse-row queries, with operations to follow a selected neighbour and return.
    Output
    Access using one current vertex and short relative paths.
    Upstream purpose
    Avoid retaining a full vertex address in every suspended recursive call.
    Approach
    Store local neighbour choices and reconstruct locations when needed. Toy describing 20 binary forward choices takes 20 bits, while one current vertex address is shared across the queries. Ingredient 8 supplies the return operation; return tokens and other call metadata still need separate space accounting.

    Space footprint of addresses and walk descriptions

    Introduces or worsens

    Missing reverse access

    §9.1 Reconstruct a task from relative fields

    A physical caller retains a short description of the child request and uses shared scratch to reconstruct its parameters. The starting point is the immutable root data. Each completed link specifies the seed transformation and task update needed for the next link.

    Physical queries

    • P-REPLAY Regenerate parameters in shared scratch

    What to prove

    Specify the concrete marked fields and prove replay on both genuine and admitted probe views, with shared scratch erased before a recursive query.

    §9.2 Expose a port and own its return path

    The logical operation maps a present port to an endpoint. Its physical realization can leave the cursor at that endpoint and return a trace. The trace owns any retained child path. Returning consumes the trace and restores the source. Discarding consumes it at the endpoint. This distinction lets the reversible walk see the terminal program's own states.

    Physical queries

    • P-INTRINSICVALID Check a candidate before outer wrap tests
    • T-INTRINSIC Terminal schedules for primitive paths
    • T-DESCRIPTOR Terminal program for a validated descriptor
    • T-RAW Terminal program for a raw-row port
    • T-FINAL Final table presence and terminal access

    What to prove

    Give the finite transition and field catalogue for the terminal programs. Check all presence, motion, return, discard, and failure cases, including synthetic states admitted to a probe.

    §9.3 Visit an endpoint and perform one action

    A restoring visit exposes a port, performs a bounded action at its endpoint, and returns. The endpoint action supplies the name bits and hit or wrap tests used by the other ingredients. In full space it can also access one shared fingerprint cell.

    Physical queries

    • P-ENDPOINT Read a name bit or test endpoint membership
    • P-VISITPOOL Visit one old or new representative and return
    • P-VISITINTRINSIC Visit an intrinsic candidate for its deferred tests
    • P-VISITRAW Visit a final raw-row port and return

    What to prove

    Prove that the actions are repeatable at the selected endpoint and that their paths and cleanup meet the restoration contract.

    §9.4 Compare names or fingerprints

    The chosen policy gives a comparison predicate for L-GROUP. Exact mode compares name bits. In the full-space mode at tight allowance, a recomputed fingerprint indexes one bit in a shared array. A flip at the first endpoint changes the bit read at the second precisely when the fingerprints agree. The repeated flip and read recover the answer and restore the array.

    Physical queries

    • P-MATCH Compare endpoints under the selected policy
    • P-KEY Short block key at a presented endpoint Full space only
    • P-ENDPOINT-KEY Read or toggle one fingerprint cell Full space only
    • P-MATCH-HASH Compare fingerprints using four restoring visits Full space only

    3 full-space-only components hidden. Switch to Full space to show them.

    What to prove

    Establish the predicate returned in each mode, restoration for arbitrary initial shared bits, and the retained fields at each visit. Analyze collision-induced changes on the logical side using Section §8.3.
