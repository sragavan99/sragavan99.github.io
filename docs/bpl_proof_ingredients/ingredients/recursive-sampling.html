    Ingredient · §7

    Recursion-friendly sampling

    Manuscript: §7, from p. 18.

    The big picture

    Map ingredient 5 · toy API

    Average successive accuracy improvements with decreasing averaging overhead.

    Input
    Successively more accurate recursive estimates, with shrinking errors, and the seed mixing operation supplied by ingredient 3.
    Output
    An accurate average for most seeds, with averaging overhead controlled across recursion.
    Upstream purpose
    Improve accuracy without paying for a large averaging description at every recursive level.
    Approach
    Write the fine estimate as coarse + (medium - coarse) + (fine - medium). Average the coarse term heavily and the smaller refinements less. Evaluate both terms of each difference on the same seed. Pay for its averaging description using the decrease in recursion budget; no independence between the terms is assumed.

    Improves

    Accumulating correlated errors; Space footprint of addresses and walk descriptions

    Introduces or worsens

    Dense rows; Numerical precision issues

    Used by tasks

    Task 3: Compute an O(16ⁱ)-sparse Eᵢ in low space; Task 4: Sparsifying from O(16ⁱ) to O(1) in low space

    §7.1 Form one sample term

    For one lower budget, the family specification gives direct, product, subtraction, copy, signal, detector, and reward contributions. The child constructor fixes the task fields and coefficients. A product uses two children under the same transformed seed, as in Section §1.1.

    Logical reference

    • L-FAMILY The finite sample expressions

    Physical queries

    • P-CHILD Construct a child task with explicit field resets
    • P-INTRINSICVALUE Answer one digit of a sample expression

    What to prove

    Check each family's term and coefficient against D-ROWFAMILIES or D-VECTORS. Prove the conditional mean and the error transfer from child values. The product bound uses pointwise support counts and the common right tuple.

    §7.2 Average differences and expose ordered arrivals

    At each lower budget average the difference from the preceding estimate. Earlier differences get longer walks. For a row, the grouped increment has both an aggregate value and an ordered list of contributing records. The list determines first representatives, multiplicities, and finite expression order in the next ingredient.

    Logical reference

    • L-AVERAGE Average successive improvements

    Physical queries

    • P-DESCRIPTOR Generate a complete candidate description
    • P-ARRIVAL One validated increment value

    What to prove

    Identify the finite average with the valid word expansion and bound its bias and centered error. Verify that the physical descriptors give the same ordered records, including valid zero contributions.

    §7.3 Accumulate detector and reward vectors

    A vector task has one scalar per source. It adds each group of scalar increments to the preceding prefix and clamps the result before processing the next group. Detector rank is formed before averaging. The final vector query is the scalar branch of L-ESTIMATE.

    Physical queries

    • P-SCALARPREFIX Scalar prefixes for vector tasks
    • P-VECTOR Final reward or detector vector query

    What to prove

    Prove scalar-prefix correspondence and count the state held across each old-prefix or arrival request.
